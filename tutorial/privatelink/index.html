AWS PrivateLink (Business Critical)

Descargar 09_devops.sql

Configurar conectividad privada entre tu VPC de AWS y Snowflake sin atravesar internet publico. Requiere edicion Business Critical o superior.

Requisitos previos​

  • Cuenta Snowflake en edicion Business Critical o superior
  • Cuenta AWS con permisos para crear VPC endpoints
  • AWS CLI configurado con credenciales validas
  • Rol ACCOUNTADMIN en Snowflake

Paso 1: Habilitar PrivateLink en Snowflake​

Generar un federated token desde AWS CLI y autorizar la cuenta:

aws sts get-federation-token --name openflow-admin

Guardar el output completo. Extraer el FederatedUserId (numero de 12 digitos).

USE ROLE ACCOUNTADMIN;

SELECT SYSTEM$AUTHORIZE_PRIVATELINK(
  '185...',           -- AWS Account ID (12 digitos)
  '{                  -- Federated token completo (JSON)
    "Credentials": {
      "AccessKeyId": "ASI...",
      "SecretAccessKey": "enw...",
      "SessionToken": "Fwo...",
      "Expiration": "2025-01-07T19:06:23+00:00"
    },
    "FederatedUser": {
      "FederatedUserId": "185...:openflow-admin",
      "Arn": "arn:aws:sts::185...:federated-user/openflow-admin"
    },
    "PackedPolicySize": 0
  }'
);

Verificar:

SELECT SYSTEM$GET_PRIVATELINK(
  '185...', '{... federated_token ...}'
);
-- Resultado esperado: "Account is authorized for PrivateLink."

Paso 2: Obtener configuracion de PrivateLink​

SELECT SYSTEM$GET_PRIVATELINK_CONFIG();

Del output JSON, guardar estos valores:

  • privatelink-vpce-id — para crear el VPC endpoint
  • privatelink-account-url — URL privada de Snowflake
  • regionless-snowsight-privatelink-url — para Snowsight
  • privatelink-ocsp-url — para validacion de certificados

Paso 3: Crear VPC Endpoint en AWS​

En la consola AWS:

  1. Ir a VPC > Endpoints > Create endpoint
  2. Seleccionar Find service by name
  3. Pegar el valor de privatelink-vpce-id
  4. Seleccionar tu VPC y subnets privadas
  5. Configurar Security Group: permitir puertos 443 y 80 desde tu CIDR
Puerto 80

El puerto 80 es necesario para el OCSP cache server de Snowflake, que valida certificados SSL. Sin el, los clientes pueden fallar al conectarse.

Paso 4: Configurar DNS (CNAME records)​

Crear registros CNAME en tu DNS privado (Route 53 o equivalente):

Registro CNAMEApunta a
<account>.privatelink.snowflakecomputing.comDNS de tu VPC endpoint
<account>.snowflakecomputing.com (regionless)DNS de tu VPC endpoint
OCSP URLDNS de tu VPC endpoint
# Verificar que resuelve a IP privada (no publica)
nslookup <account>.us-east-1.privatelink.snowflakecomputing.com
Validacion

El DNS debe resolver a IPs privadas dentro de tu VPC. Si resuelve a IPs publicas, el registro CNAME no esta configurado correctamente.

Paso 5: Gateway endpoint para S3​

Los clientes de Snowflake necesitan acceso a S3 para operaciones internas. Crear un gateway endpoint para que el trafico no salga a internet:

VPC > Endpoints > Create endpoint
  Service: com.amazonaws.<region>.s3 (tipo Gateway)
  VPC: tu VPC
  Route tables: las de tus subnets privadas

Paso 6: Conectar clientes​

Los clientes se conectan usando la URL privada:

# Formato de host
<account>.<region>.privatelink.snowflakecomputing.com

# Ejemplo
xy12345.us-east-1.privatelink.snowflakecomputing.com

Para Snowflake CLI:

snow connection add \
  --account xy12345.us-east-1.privatelink \
  --user myuser

Paso 7 (recomendado): Bloquear acceso publico​

Despues de validar la conectividad privada, crear una network policy que solo permita trafico desde tu VPC:

CREATE NETWORK RULE private_only
  MODE = INGRESS
  TYPE = IPV4
  VALUE_LIST = ('10.0.0.0/8');  -- Tu rango CIDR

CREATE NETWORK POLICY private_access_only
  ALLOWED_NETWORK_RULE_LIST = ('private_only');

ALTER ACCOUNT SET NETWORK_POLICY = private_access_only;

Verificacion con SnowCD​

Snowflake proporciona una herramienta de diagnostico de conectividad:

SELECT SYSTEM$ALLOWLIST_PRIVATELINK();

Usar SnowCD para validar que todos los endpoints estan accesibles via PrivateLink antes de bloquear acceso publico.
