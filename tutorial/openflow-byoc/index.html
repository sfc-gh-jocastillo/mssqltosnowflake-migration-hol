Openflow BYOC en AWS

Desplegar Openflow en tu propia cuenta AWS (Bring Your Own Cloud). Los datos nunca salen de tu VPC.

Que es Openflow​

Openflow es el servicio de integracion de datos de Snowflake, basado en Apache NiFi. Permite conectar cualquier fuente de datos con Snowflake usando conectores pre-construidos o flujos personalizados.

BYOC (Bring Your Own Cloud) despliega el runtime de Openflow dentro de tu VPC en AWS, dando control total sobre networking, seguridad y compliance.

AspectoOpenflow Snowflake DeploymentOpenflow BYOC
InfraestructuraGestionada por Snowflake (SPCS)Tu cuenta AWS (EKS)
NetworkingEgress via EAIControl total del VPC

Requisitos previos​

Snowflake​

USE ROLE ACCOUNTADMIN;

-- Crear rol de administracion Openflow
CREATE ROLE IF NOT EXISTS OPENFLOW_ADMIN;
GRANT CREATE OPENFLOW DEPLOYMENT ON ACCOUNT TO ROLE OPENFLOW_ADMIN;
GRANT CREATE DATABASE ON ACCOUNT TO ROLE OPENFLOW_ADMIN;
GRANT ROLE OPENFLOW_ADMIN TO USER <tu_usuario>;

-- Habilitar secondary roles para usuarios Openflow
ALTER USER <openflow_user> SET DEFAULT_SECONDARY_ROLES = ('ALL');
Roles no permitidos

Al acceder a Openflow UI, NO usar ACCOUNTADMIN, ORGADMIN, GLOBALORGADMIN, ni SECURITYADMIN. Usar un rol personalizado como OPENFLOW_ADMIN.

AWS​

  • Cuenta AWS con permisos para crear CloudFormation stacks
  • Permisos para crear EKS, EC2, IAM roles, VPC endpoints
  • Si usas VPC existente (BYO-VPC):
    • 2 subnets publicas (diferentes AZs, minimo /27)
    • 2 subnets privadas (diferentes AZs, minimo /24)
    • Conectividad a Snowflake desde las subnets privadas

Paso 1: Crear el deployment​

  1. En Snowsight: Ingestion > Openflow > Launch Openflow
  2. Create a deployment
  3. Seleccionar Amazon Web Services
  4. Elegir Managed VPC o Bring your own VPC
  5. (Opcional) Habilitar PrivateLink para comunicacion interna
  6. (Opcional) Habilitar Custom Ingress si no hay internet publico
  7. Create Deployment — descargar el template CloudFormation

Paso 2: Aplicar CloudFormation​

En AWS Console:

  1. Ir a CloudFormation > Create stack > Upload template
  2. Subir el template descargado
  3. Si es BYO-VPC, seleccionar tu VPC y subnets en los dropdowns
  4. Ejecutar el stack

El stack crea:

  • VPC con subnets (si es Managed VPC)
  • NAT Gateway para egress
  • EC2 instance para el Openflow Agent
  • S3 bucket para estado de Terraform
  • IAM roles y policies

La instalacion completa toma ~45 minutos.

Paso 3: Network policy (si aplica)​

Si tienes network policies en Snowflake, agregar la IP del NAT Gateway:

USE ROLE ACCOUNTADMIN;

CREATE NETWORK RULE allow_openflow_deployment
  MODE = INGRESS
  TYPE = IPV4
  VALUE_LIST = ('<NAT_GATEWAY_PUBLIC_IP>/32');

-- Agregar a tu policy existente
SHOW PARAMETERS LIKE 'NETWORK_POLICY' IN ACCOUNT;

ALTER NETWORK POLICY <tu_policy>
  ADD ALLOWED_NETWORK_RULE_LIST = (allow_openflow_deployment);

Paso 4: Crear el execute-as role​

El execute-as role es la identidad que usan los conectores para escribir en Snowflake:

USE ROLE ACCOUNTADMIN;

CREATE ROLE IF NOT EXISTS OPENFLOW_EXECUTE_AS_RL;

-- Warehouse dedicado para ingestion
GRANT USAGE, OPERATE ON WAREHOUSE ETL_WH
  TO ROLE OPENFLOW_EXECUTE_AS_RL;

-- Acceso a base de datos destino
GRANT USAGE ON DATABASE SNOWFLAKE_POC
  TO ROLE OPENFLOW_EXECUTE_AS_RL;
GRANT USAGE ON SCHEMA SNOWFLAKE_POC.RAW
  TO ROLE OPENFLOW_EXECUTE_AS_RL;
GRANT CREATE TABLE ON SCHEMA SNOWFLAKE_POC.RAW
  TO ROLE OPENFLOW_EXECUTE_AS_RL;

-- Asignar a usuario
GRANT ROLE OPENFLOW_EXECUTE_AS_RL TO USER <openflow_user>;

Paso 5: Crear un runtime​

  1. En Openflow UI: Create a runtime
  2. Seleccionar tu deployment
  3. Elegir Node type (tamano de EC2)
  4. Configurar rango Min/Max nodes para auto-scaling
  5. Create

El runtime queda listo en ~2 minutos. Al hacer click se abre el canvas de Openflow (interfaz NiFi).

Paso 6 (opcional): Configurar PrivateLink para Openflow​

-- Obtener URLs de PrivateLink
SELECT SYSTEM$GET_PRIVATELINK_CONFIG();
-- Guardar: openflow-privatelink-url, external-telemetry-privatelink-url

En AWS:

  1. Crear VPC endpoint con el privatelink-vpce-id
  2. Crear Route 53 private hosted zone: privatelink.snowflakecomputing.com
  3. Agregar CNAME records para las URLs de Openflow
  4. Configurar Security Group del VPC endpoint

Verificacion​

-- Verificar deployment (gen 2)
SHOW OPENFLOW DEPLOYMENTS;

-- Verificar runtimes
SHOW OPENFLOW RUNTIMES;

En la UI de Openflow, el deployment debe mostrar estado Active y el runtime debe estar Running.

Event table (recomendado)​

Configurar una event table dedicada para monitoreo:

CREATE EVENT TABLE IF NOT EXISTS SNOWFLAKE_POC.RAW.OPENFLOW_EVENTS;

ALTER OPENFLOW DEPLOYMENT <deployment_name>
  SET EVENT_TABLE = 'SNOWFLAKE_POC.RAW.OPENFLOW_EVENTS';
